# @simplix-react/gantt

[English](/en/packages/gantt/README.md) | **한국어**

React용 프로젝트 Gantt 차트입니다. 셀을 바로 편집하는 작업 표와, 막대를 끌어 일정을 바꾸고 작업을 연결하는 타임라인을 나란히 표시합니다. 중요 경로, 초기 계획, 자원 시트, 자원 사용 현황, 실행 취소와 다시 실행, Microsoft Project XML 교환을 제공합니다.

차트는 `@simplix-react/ui` 컴포넌트와 테마 토큰으로 그리고, 일정은 `@simplix-react/gantt-core`로 계산합니다.

## 설치

```bash
pnpm add @simplix-react/gantt @simplix-react/gantt-core
```

Tailwind가 차트의 클래스를 인식하도록 프레임워크 테마 뒤에서 스타일시트를 한 번 불러오세요.

```css
@import "tailwindcss";
@import "@simplix-react/ui/theme.css";
@import "@simplix-react/gantt/styles.css";
```

## 빠른 시작

```tsx
import { Gantt } from "@simplix-react/gantt";
import type { Project } from "@simplix-react/gantt-core";

export function PlanPage({ plan, onSave }: { plan: Project; onSave: (plan: Project) => void }) {
  return (
    <div className="h-[720px]">
      <Gantt defaultProject={plan} onChange={(project) => onSave(project)} />
    </div>
  );
}
```

높이가 정해진 상자 안에 차트를 넣으세요. 차트는 상자를 가득 채우고 그 안에서 스크롤합니다. 차트는 `defaultProject`로 받은 계획을 그 뒤로 직접 관리하며, 확정한 모든 변경(실행 취소와 다시 실행 포함)을 `onChange(project, schedule, changes)`로 알립니다. `changes`에는 직전 계획과 달라진 레코드가 들어 있어, 서버는 이 목록으로 편집 내용을 저장할 수 있습니다.

다른 사용자가 저장한 편집처럼 다른 곳에서 바뀐 계획을 반영하려면 `store.getState().merge(base, theirs)`를 호출하세요. `base`는 양쪽이 함께 출발한 계획입니다. 상대만 바꾼 레코드는 받아들이고, 양쪽이 모두 바꾼 레코드는 이쪽 버전을 유지하고 충돌로 돌려주며, 실행 취소 기록은 유지합니다. 차트는 충돌을 대화 상자에 나열하고, 사용자는 상대 버전으로 바꿀 레코드를 고릅니다. 코드에서는 `settleMerge(conflicts)`가 같은 일을 하며, 이 선택은 한 번의 실행 취소 단위입니다. `sync(project)`는 병합하지 않고 계획 전체를 교체합니다.

계획은 `@simplix-react/gantt-core`의 `serializeProject(project)`로 저장하고 `parseProject(text)`로 다시 읽으세요. 저장한 텍스트에 형식 이름과 버전을 기록하므로, 더 새로운 버전이 저장한 계획은 잘못 읽지 않고 거부하며, 버전 표기 없이 저장한 프로젝트는 그대로 엽니다.

계획 화면 만들기, 계획 저장, 사용자별 화면 배치 보관은 [docs/guide.ko.md](/ko/packages/gantt/docs/guide.md)의 안내를 참고하세요.

## 차트의 기능

| 영역 | 동작 |
| --- | --- |
| 작업 표 | 머리글 오른쪽 경계의 손잡이를 끌어 열 너비를 바꿉니다(두 번 누르면 기본 너비). 머리글을 끌면 열을 이동합니다. 끄는 동안 포인터 옆에 열 이름을 표시하고, 놓을 경계에 표 전체 높이의 선을 긋고, 표 가장자리에 머무르면 열을 스크롤합니다. 표 모서리와 도구 모음의 열 버튼에서 열을 표시하거나 숨깁니다. 열 너비의 합이 표보다 넓으면 표 아래 막대, 가로 휠, 손가락으로 표를 옆으로 스크롤하며, 행 번호 열과 첫 번째 열은 고정됩니다. 활성 셀과 방금 추가한 열까지는 자동으로 스크롤합니다. 표와 타임라인 사이 분할선으로 표 너비를 바꿉니다. 열 손잡이와 분할선은 키보드로도 조작합니다. 방향키로 크기를 바꾸고, Shift를 누르면 한 번에 더 많이 바뀌며, Home은 열을 기본 너비로 되돌립니다. 행 번호를 끌면 행을 이동하며, 행 번호 열은 가장 긴 번호와 옆 표시가 들어가는 너비만 차지합니다. 행이나 막대를 마우스 오른쪽 버튼으로 누르면 선택한 작업의 명령을 엽니다. 기간은 사용자의 언어로 표시하고(`3일`, `2주`) 그 형식과 영문자 형식을 모두 읽습니다. 요약 작업은 접고 펼 수 있습니다. 두 번 누르기, F2, Enter, 문자 입력으로 셀을 편집합니다. 편집할 수 있는 셀은 이름, 기간(`3d`, `2w`, `4h`, `2ed`), 시작, 완료, 선행 작업(`3`, `4SS+2d`, `5FF-1d`), 완료율입니다. |
| 타임라인 | 두 줄 날짜 머리글과 분기부터 시간까지의 확대 단계(`ZOOM_LEVELS`)를 제공하고, 근무 시간이 아닌 구간을 프로젝트 달력에 따라 음영으로 표시합니다. |
| 필터, 정렬, 그룹 | 도구 모음 메뉴에서 중요 작업, 미완료 작업, 완료한 작업, 늦은 작업, 자원 미배정 작업, 마일스톤, 한 자원의 작업으로 행을 좁히고, 열 기준으로 정렬하거나, 자원별, 상태별, 중요 여부별 머리행 아래에 모읍니다. 검색란은 이름으로 좁힙니다. |
| 막대 | 막대 옆에 자원 이름, 작업 이름, 진행률, 날짜를 표시하거나 아무것도 표시하지 않습니다. 막대 색은 차트 색, 작업 자체 색, 자원별 색 가운데 하나입니다. 진행선은 상태 기준일에서 모든 작업의 진행 지점을 잇습니다. 메모나 날짜 제약 조건이 있는 작업은 행 번호 열에 표시합니다. |
| 다른 보기 | 단계별로 확대하고 화면에 맞출 수 있는 네트워크 다이어그램(열을 건너뛰는 선은 상자 사이로 지나감), 작업을 다른 날로 끌면 그 날수만큼 이동하는 월 달력, 작업량을 가용량과 비교하는 자원 그래프, 배정별 시간을 보여 주는 작업 배정 현황 표가 있습니다. 사용 현황 표와 그래프는 화면에 보이는 행과 열만 그립니다. |
| 보기 전용 | `readOnly`는 계획을 보여 주기만 하고 모든 편집을 거부합니다. |
| 화면 배치 | 열 너비, 순서, 표시 여부, 확대 단계, 접은 행, 보기, 표시 영역(표, 타임라인, 둘 다), 막대 설정을 `layout` 값 하나로 묶습니다. `onLayoutChange`로 알리고 `layout`으로 다시 받습니다. |
| 좁은 화면 | 작업 표는 차트 너비의 45% 이하로 열리고 차트 전체를 차지하지 않으므로 타임라인이 항상 보입니다. 메뉴에서 표만 또는 타임라인만 표시할 수 있습니다. 보기 전환은 명령 위 별도 줄에 탭으로 놓이고, 탭이 들어가지 않으면 목록으로 바뀝니다. 도구 모음이 560px보다 좁으면 실행 취소, 추가, 삭제, 열 목록, 검색만 남기고 나머지 명령은 메뉴에 나열합니다. 사용 현황 보기는 이름에 너비의 40%까지만 내어 주고, 자원 시트는 입력할 수 있는 너비의 필드로 옆으로 스크롤하며, 달력은 날마다 작업을 표시하고 고른 날의 작업을 이름으로 나열합니다. 대화 상자는 필드를 한 열로 배치합니다. |
| 날짜 표시선 | 오늘, 상태 기준일, 계획의 시작과 끝마다 고유한 색의 선과 머리글의 이름표를 표시합니다. 이름표는 날짜가 표 쪽으로 스크롤되는 동안 표 옆에 온전히 남고, 날짜가 표 아래로 들어가면 사라집니다. 오늘 날짜에는 색을 입히고, 버튼으로 오늘까지 스크롤합니다. 오늘이 계획에서 한 달 이내면 타임라인을 오늘까지 넓힙니다. 표시선은 끌 수 있고 PDF에도 포함됩니다. |
| 막대 편집 | 막대를 끌면 작업을 이동하고, 끝을 끌면 크기를 바꾸고, 막대 아래 표시를 끌면 진행률을 정합니다. 요약 작업은 대괄호로, 마일스톤은 마름모로 그립니다. 기한은 화살표로 그립니다. |
| 연결 | 막대 끝의 점에서 다른 막대로 끌어 연결합니다. 시작한 끝과 놓은 끝에 따라 완료-시작, 시작-시작, 완료-완료, 시작-완료가 정해집니다. 연결선을 눌러 선택하고 Delete로 삭제합니다. 위반한 연결은 점선입니다. 연결선은 타임라인, 네트워크 다이어그램, PDF 모두에서 꺾이는 모서리를 곡선으로 그립니다. |
| 터치 화면 | 손가락을 대자마자 움직이면 막대, 열 머리글, 행 번호, 달력의 작업 어디에서 시작하든 차트를 스크롤합니다. 손가락을 300ms 동안 대고 있으면 대상을 집어 끕니다. 마우스와 펜은 바로 끕니다. |
| 고대비 테마 | 강제 색상(Windows 고대비 테마)에서 요약 막대, 마일스톤, 진행률, 초기 계획, 근무 시간이 아닌 구간, 날짜 표시선을 테마 색으로 채웁니다. 그 환경에서는 색상으로 구분할 수 없으므로 중요 작업은 이중 외곽선, 선택한 막대는 강조 외곽선으로 표시합니다. |
| 화면 낭독기 | 표는 표시 순서대로 행을 세는 그리드이며, 머리글 행이 첫 행입니다. 막대는 작업 이름, 날짜, 진행률로 읽고, 마일스톤이나 중요 작업이면 그 사실을 함께 읽습니다. |
| 중요 경로 | 중요 작업과 그 작업을 결정하는 연결을 destructive 색으로 그립니다. |
| 초기 계획 | 현재 날짜를 저장한 뒤 각 작업 아래 가는 막대로 표시합니다. `startVariance`, `finishVariance` 열은 작업이 얼마나 움직였는지 보여 줍니다. |
| 프로젝트 정보 | 계획 이름, 시작일 또는 완료일, 상태 기준일, 달력을 정하고, 모든 달력의 요일별 근무 시간과 예외일을 편집합니다. |
| 비용 | `work`, `cost` 열은 자원 단가, 사용당 비용, 고정 비용으로 작업마다 합산하고 요약 작업으로 올려 합산합니다. |
| 사용자 지정 필드 | 텍스트, 숫자, 날짜, 플래그 필드를 프로젝트 정보 대화 상자에서 정의하고, 작업 정보 대화 상자에서 편집하며, `custom:<field id>` 열로 표시합니다. |
| 분할 작업 | 작업 정보 대화 상자에서 작업을 한 날짜부터 정한 근무 시간만큼 중단합니다. 막대는 중단 구간을 비어 있는 점선으로 그립니다. |
| 반복 작업 | 대화 상자에서 매일, 매주, 매월 반복마다 작업 하나씩을 둔 요약 작업을 추가합니다. |
| 클립보드 | 복사하면 선택한 작업을 탭으로 구분한 텍스트로 시스템 클립보드에 넣습니다. 붙여넣기는 스프레드시트의 행을 받아 한 줄에 작업 하나를 만들고, 첫 번째 셀을 이름, 두 번째 셀을 기간으로 읽습니다. |
| PDF | 계획을 A4 가로 PDF 파일로 그립니다. 모든 장에 작업 표를 넣고, 행은 아래 장으로 이어지며 타임라인은 옆으로 최대 여섯 장까지 이어집니다. 화면에 보이는 행을 화면의 순서와 막대 색, 행 묶음 머리글과 함께 그리므로, 필터나 접은 요약 작업이 숨긴 행은 빠집니다. 그리는 함수는 `@simplix-react/gantt/pdf`에서 내보내며, 차트는 처음 PDF를 요청받을 때 그 함수를 불러옵니다. |
| 인쇄 | 계획을 가로 용지에 맞춰 배치합니다. 화면에 보이는 모든 행과 표의 모든 열을 페이지 너비에 맞는 확대 단계로 넣고, 페이지의 나머지 부분은 인쇄하지 않습니다. |
| 자원 | 자원 시트에서 자원을 편집하고, 작업 정보 대화 상자에서 배정합니다. 사용 현황 화면은 날마다(긴 계획은 주마다) 배정된 시간을 합산하고 초과 배정 칸을 표시합니다. |
| 자원 평준화 | 초과 배정된 자원이 없어질 때까지 작업을 늦춥니다. 여유 시간 안에서만 늦추거나 작업을 분할하도록 지정할 수 있고, 평준화를 다시 지울 수 있습니다. |
| 진행 | 상태 기준일을 정하면 끝내지 못한 작업을 그 뒤로 이동하고, 계획 가치, 획득 가치, 실제 비용, 일정 차이, 비용 차이를 열로 표시합니다. |
| 충돌 | 충돌 개수를 누르면 충돌한 작업 목록을 엽니다. 하나를 고르면 그 작업을 선택하고 그 위치로 스크롤합니다. |
| 실행 취소 | 모든 편집은 한 단계입니다. Ctrl/Cmd+Z는 실행 취소, Ctrl/Cmd+Shift+Z 또는 Ctrl/Cmd+Y는 다시 실행입니다. |
| 교환 | 도구 모음 메뉴에서 Microsoft Project XML을 읽고 씁니다. 내보내기 전에는 파일에 담을 수 없는 내용을, 가져온 뒤에는 파일과 다르게 읽은 내용을 나열합니다. |
| 계획 파일 | 계획 전체를 담은 `.gantt.json` 파일로 저장하고, 그 파일을 엽니다. |
| 빈 계획 | 작업이 없는 계획에는 첫 작업을 추가하는 버튼을 표시합니다. |
| 큰 계획 | 화면에 보이는 행과 머리글 칸만 그립니다. |

엔진이 거부한 편집(연결 순환, 기간으로 읽을 수 없는 값)은 계획을 바꾸지 않고, 그 이유를 도구 모음 아래에 표시합니다.

### 키보드

| 키 | 동작 |
| --- | --- |
| 위쪽 방향키, 아래쪽 방향키 | 선택을 옮깁니다. Shift와 함께 누르면 선택을 넓힙니다 |
| 왼쪽 방향키, 오른쪽 방향키, Tab | 활성 셀을 행 안에서 옮깁니다 |
| Alt+왼쪽 방향키, Alt+오른쪽 방향키 | 선택한 작업을 근무일 하루만큼 옮깁니다 |
| Ctrl/Cmd+휠 | 타임라인을 확대하거나 축소합니다 |
| Ctrl/Cmd+D | 처음 선택한 행의 활성 셀을 나머지 선택한 행에 복사합니다 |
| Insert | 선택한 행 아래에 작업을 추가합니다 |
| Delete | 선택한 연결을, 없으면 선택한 작업을 삭제합니다 |
| F2, Enter, 아무 문자 | 선택한 작업의 활성 셀을 편집합니다 |
| Alt+Shift+오른쪽 방향키, Alt+Shift+왼쪽 방향키 | 한 수준 내리기, 한 수준 올리기 |
| Ctrl/Cmd+C, Ctrl/Cmd+V | 작업을 작업 사이의 연결과 함께 복사하고 붙여넣습니다 |
| Escape | 선택을 지우거나 끌기를 취소합니다 |

## 속성

`Gantt`는 `GanttProvider`와 `GanttShell`의 속성을 받습니다.

| 속성 | 타입 | 기본값 | 설명 |
| --- | --- | --- | --- |
| `defaultProject` | `Project` | 필수 | 차트가 처음 여는 계획 |
| `onChange` | `(project, schedule, changes) => void` | | 확정한 변경마다 직전 계획과 달라진 레코드와 함께 호출 |
| `columns` | `GanttColumnId[]` | `DEFAULT_COLUMNS` | 작업 표가 처음 여는 열과 순서. `BUILT_IN_COLUMNS`에 기본 제공 열이 모두 있고, `custom:<field id>`는 사용자 지정 필드를 표시 |
| `levelingOptions` | `LevelingOptions` | `{}` | 자원 평준화가 할 수 있는 일: `withinSlack`, `split` |
| `readOnly` | `boolean` | `false` | 계획을 보여 주기만 하고 모든 편집을 거부 |
| `layout` | `Partial<GanttLayout>` | | 처음 열 때 적용할 저장한 화면 배치 |
| `onLayoutChange` | `(layout) => void` | | 화면 배치가 바뀔 때 전체 배치와 함께 호출 |
| `defaultGridWidth` | `number` | 열에 맞춘 너비, 최대 560과 차트의 45% | 작업 표의 처음 너비 |
| `weekStartsOn` | `number` | `0` | 주 단위 열의 첫 요일. 0은 일요일 |
| `zoom` | `number` | `4` | `ZOOM_LEVELS`의 인덱스 |
| `view` | `GanttView` | `"gantt"` | 처음 표시할 화면: `gantt`, `network`, `calendar`, `resources`, `usage`, `taskUsage`, `graph` |
| `showCriticalPath` | `boolean` | `false` | |
| `showLinks` | `boolean` | `true` | |
| `showMarkers` | `boolean` | `true` | 오늘, 상태 기준일, 계획의 시작과 끝을 표시 |
| `baselineNumber` | `number \| null` | `null` | 막대 아래에 그릴 초기 계획 |
| `xmlExchange` | `boolean` | `true` | Microsoft Project XML 명령 표시 |
| `planFiles` | `boolean` | `true` | 계획 파일 저장과 열기 명령 표시 |
| `trailing` | `ReactNode` | | 도구 모음 끝에 추가할 컨트롤 |
| `emptyState` | `ReactNode` | | 작업이 없는 계획의 안내 문구를 대체 |
| `className` | `string` | | 차트 바깥 요소에 추가할 클래스 이름 |

## 포함하지 않는 기능

- PDF 파일은 장마다 이미지로 담으므로 텍스트를 선택하거나 검색할 수 없습니다. 브라우저 인쇄는 넓은 계획을 페이지 너비 하나에 맞춰 줄이며, 여러 장으로 나누는 것은 PDF 내보내기입니다.
- 붙여넣은 스프레드시트 행에서는 이름과 기간만 읽습니다. 그 뒤 셀의 날짜, 연결, 자원은 읽지 않습니다.
- Microsoft Project XML에는 분할 작업의 중단 구간, 작업별 색상, 반복 작업의 반복 규칙, Microsoft Project가 종류별로 제공하는 개수를 넘는 사용자 지정 필드를 담을 수 없습니다. 차트는 내보내기 전에 이를 알립니다.
- Microsoft Project XML에서 읽은 사용자 지정 필드는 Microsoft Project가 지정한 ID(`text1`, `number3`)를 쓰므로, 내보내고 다시 가져오기 전에 저장한 `custom:<id>` 열은 다시 골라야 합니다.
- 하위 프로젝트는 요약 작업 아래에 복사본으로 삽입합니다. 원래 파일과 동기화하지 않으며, 그 파일의 달력, 초기 계획, 사용자 지정 필드는 가져오지 않습니다.
- 반복 작업을 바꾸면 반복 작업을 새로 만들며, 이전 반복 작업의 진행률과 연결은 유지하지 않습니다.
- 아래로 채우기는 이름, 기간, 실제 비용, 사용자 지정 필드를 복사합니다. 날짜와 선행 작업은 채우지 않습니다.
- 네트워크 다이어그램에서 두 선이 두 행이나 두 열 사이 간격의 같은 구간을 함께 지날 수 있습니다.
- 종단 간 테스트는 Storybook이 실행 중이고 Google Chrome이 설치되어 있어야 하며, `pnpm test`에 포함되지 않습니다. Storybook은 빌드한 패키지에서 차트의 스타일시트를 읽으므로, `src/styles.css`를 바꾸면 먼저 `pnpm --filter @simplix-react/gantt build`를 실행해야 하고, 두 파일이 다르면 테스트를 중단합니다. Storybook이 디스크보다 오래된 소스 파일을 제공할 때도 중단하는데, 파일 감시가 느릴 때 생깁니다. Storybook을 다시 시작하면 해결되고, 감시가 늦는 컴퓨터에서는 `CHOKIDAR_USEPOLLING=1`로 시작하면 다시 생기지 않습니다. `Gantt` 워크플로가 이 패키지들이 바뀔 때 테스트를 실행합니다.
- 터치는 Google Chrome에서 확인했습니다. 펜은 마우스처럼 바로 끌기 때문에, 펜으로도 스크롤하는 기기에서는 스크롤이 끌기를 가로챌 수 있습니다.
- 선행 작업 목록의 지연 시간은 모든 언어에서 단위 영문자로 씁니다(`4SS+2d`).
- Microsoft Project XML 읽기와 쓰기는 메인 스레드에서 실행합니다. 작업 20,000개인 계획은 페이지를 약 0.5초 동안 멈추게 하며, 그동안 불러오는 중 표시를 보여 줍니다.

## 구성

기본 셸이 맞지 않으면 부품을 조합하세요.

```tsx
import { GanttChart, GanttProvider, GanttToolbar, ProjectDialog, TaskDialog, useGantt, useGanttStore } from "@simplix-react/gantt";

function FinishDate() {
  const finish = useGantt((state) => state.schedule.finish);
  return <span>{finish}</span>;
}

<GanttProvider defaultProject={plan} columns={["wbs", "name", "duration", "totalSlack"]}>
  <GanttToolbar trailing={<FinishDate />} />
  <GanttChart />
  <TaskDialog />
  <ProjectDialog />
</GanttProvider>;
```

`useGanttStore()`는 차트의 스토어를 돌려줍니다. `store.getState().apply(label, edit)`는 `@simplix-react/gantt-core`의 어떤 함수든 실행 취소 단계 하나로 실행하고, `load(project)`는 계획을 교체하고 실행 취소 기록을 지웁니다. `createGanttStore(project, options)`는 React 밖에서 스토어를 만듭니다.

다른 화면도 따로 내보냅니다: `ResourceSheet`, `ResourceUsage`, `ResourceGraph`, `TaskUsage`, `CalendarView`, `NetworkDiagram`, `ColumnChooser`, `RecurringDialog`. `GanttShell`은 프로바이더를 뺀 기본 도구 모음, 화면, 대화 상자입니다. PDF 함수 `downloadPdf`, `layoutPdf`, `pdfRows`, `renderPdf`, `buildPdf`는 `@simplix-react/gantt/pdf`에서 가져옵니다.
